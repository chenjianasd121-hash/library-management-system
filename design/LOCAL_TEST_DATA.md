## 可直接操作的场景

1. 读者一查看“我的借阅”：`【测试】三体`可测试续借，`【测试】活着`已续借一次。
2. `【测试】时间简史`只有一册：读者一待取，读者二排队；条码 `TEST1022-010-01`。馆员先为读者一借出，再归还，可以观察读者二转为待取。
3. `【测试】代码大全`没有副本，读者一处于排队；可由馆员新增副本观察自动分配。
4. 逾期读者借阅 `【测试】算法导论`，条码 `TEST1022-009-01`。馆员归还后，该测试读者的逾期限制应解除。
5. 切换读者二的“已归还”筛选查看历史；员工统计页可查看最近 30 天的多日借还趋势。
6. 公告管理可以查看草稿/撤下状态，公开公告仅能看到已发布内容。

完整新增 ID、条码与初始验证快照见 `local-test-data-result.json`。操作后状态会正常改变，快照不会随页面操作自动更新。

## 生成与检查点

`seed-local-test-data.ps1` 的密码从必填参数传入，未在脚本中写死。它通过真实业务 API 创建记录，仅为新注册的测试管理员设置初始角色，并为新建测试借阅调整历史/逾期日期；所有 SQL 都限定于本批新建 ID。

各阶段检查点保存在 `output/runtime/local-test-seed/checkpoint.json`。脚本检测到已有检查点或同名账号会停止，不会覆盖已有账号或重复播种；不要删除检查点后盲目重跑。

本次验证为接口及前端代理验证，不代表 Chrome 视觉验收已完成。视觉任务状态仍见根目录 `design-qa.md`。
