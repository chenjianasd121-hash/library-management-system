## 截图条件与证据

使用独立后台 Google Chrome，当前本机 5173/5174/5175 和真实 8080 后端；业务接口只允许 GET，登录/退出例外。没有修改业务数据、复用日常浏览器用户目录或伪造成功响应。

Chrome 新上下文、100% 缩放、deviceScaleFactor 1、sRGB、Asia/Shanghai。原图尺寸逐张使用 manifest 值（多数为 1487×1058，馆员借出为 1486×1058等），不把设计图拉伸到统一尺寸。实际页面像素、DOM 几何、字体和颜色记录在每条 `matrix.json` 的 captures 中。

`matrix.json` 保存完整页面/状态映射、原图哈希、截图路径/哈希、视口和审阅状态；`capture-summary.json` 保存页面健康结果；`comparison-manifest.json` 保存对照证据；`review.json` 保存首轮差异；`color-samples.json` 保存局部原始 RGB。`checkpoint.json` 指明下一未完成项。

真实书名、统计数量、姓名、日期和未上传封面的业务数据与设计示例有差异，须单独标明，不能因此硬编码页面数据。色彩记录是图片 RGB 采样，不是显示器校色、Delta E 或全站“还原率”。

每轮处理最多三个画面的视觉修订，保存改前/改后证据，再做同尺寸、同状态比较；不能只凭构建通过宣布还原完成。先修共用导航/字体/颜色与三端登录，再修首页和借还主流程，之后逐页完成其余页面及弹窗状态。视觉修改后复核相关真实交互，避免回退已经通过的流程修复。

## 继续和复跑

已有截图优先复用；中断后读取 `output/visual-acceptance/current-run.txt` 和对应检查点，不重复启动 `--prepare`。

从 `frontend` 执行：

```powershell
npm run qa:visual:capture
npm run qa:visual:viewer
npm run qa:visual:compare -- --ids=admin-login,reader-login,librarian-public-login --focus=form
```

`capture` 会跳过已有三档截图。只读准备馆员“已核验”状态使用 `node tests/visual-acceptance.mjs --ids=librarian-checkout --verified-checkout`。`compare` 每轮最多 3 个画面；修改产品样式之后需另存新一轮截图/版本，不能拿旧截图判定修复成功。

需要重开对照服务时，在项目根目录读取运行目录后执行：

```powershell
$visualRun = (Get-Content output/visual-acceptance/current-run.txt -Raw).Trim()
python -m http.server 5280 --bind 127.0.0.1 --directory $visualRun
```

只服务验收目录，不能把项目根目录或含密码的运行目录作为静态站点。首次新建基线才执行 `npm run qa:visual:prepare`。本轮不对外发布，不提交截图输出或账号密码。
